# Website, SEO and AI visibility opportunities

This guide is for the initiating conversation using Dig. It coordinates ordinary source methods; it does not create a master service, persistent specialist or new source report type. Use it when the question concerns how a website gets found, why competitors appear in search or AI answers, and which concrete changes could help.

## Start with the decision

Read available project context and saved reports first. Establish the website and brand aliases, priority offering/customer, market/language, business outcome and important pages. Keep business competitors, search competitors and independent citation sources distinct. Ask only when a missing detail changes entity matching, market or the proposed work. State assumptions; do not buy broad keyword lists before knowing what the business wants discovered.

Choose focused diagnosis, opportunity review or market review to match the decision. Scope is adaptive, not a permanent tiny query/competitor cap. Work in bounded batches with the user's provider-spend authorization. Expand only when a meaningful intent, competitor, market difference, conflict or missing page comparison could change the answer. Stop repetitive or irrelevant branches and disclose unavailable evidence and budget boundaries. Existing authorization carries forward; do not repeatedly request the same approval.

## Build the evidence chain

1. Map customer intent. Owner GSC/analytics/Bing exports, if supplied, can identify actual property queries and outcomes. DataForSEO Labs and LLM Mentions can discover candidate queries and questions. Keep owner observations, provider estimates and agent-written prompt hypotheses separate. Group by the customer's task rather than creating a page for each keyword.
2. Select the acquisition mode. Use DataForSEO's database for discovery; fresh SERP or consumer-surface observations only when freshness could change a recommendation. An API-model experiment is a different population from consumer-app visibility. Match market, language, device, dates and entity rules before comparing.
3. Read the actual answer/result. Distinguish a prose mention, an actual citation, a merely retrieved page, an ambiguous namesake and an absence within the collected scope. Do not use a brand-filtered sample as the denominator for an absence rate. Failed or pending calls are unknown, never zero.
4. Read the pages behind the finding. Use the Exa method for exact cited/competing URLs and the relevant owned page, or run it inline. If necessary, use the host's permitted browser/source reading or narrow DataForSEO OnPage inspection for directives, canonical and rendering evidence. A snippet cannot establish a full page's contents, and text extraction cannot establish HTTP/index eligibility. A DataForSEO worker returns a page-reading queue to the parent; it never silently runs another source.
5. Compare the evidence. Tie each material query or answer to its cited/competing page and an inspected owned page. Preserve separate Dig retrieval times, provider observation dates and page dates. A citation does not prove why a page was selected. If the owned page is unavailable or uninspected, say so instead of inventing a gap.
6. Diagnose before recommending. Separate access/index eligibility, intent mismatch, missing facts/proof, positioning/entity ambiguity, third-party coverage, authority, ad/landing continuity and conversion. A visibility estimate cannot establish a conversion problem or competitor profitability. Existing Google guidance says ordinary SEO foundations apply to AI features; special AI files or schema are not a default prescription.
7. Propose and verify. Each action names the URL or proposed page, customer question, exact change, supporting passages/call references, expected mechanism, diagnosis confidence, outcome uncertainty and verification step. Distinguish demonstrated fixes, experiments and investigations. Keep other examined candidates and why they were not recommended. Do not invent revenue/citation lift, effort hours or an aggregate SEO score.

## Ordinary workers and evidence obligations

Choose `dataforseo` for quantitative search/competitor/technical/ad evidence, `dataforseo-ai-visibility` for AI answer/citation research, and `exa` for page evidence. Other social/ad sources belong only when they answer a specific branch. Give each worker a complete assignment, explicit project/dig and its source's skillPath. Read every relied-on report in full and its load-bearing originals before joining the findings.

The specialist context belongs in the assignment or existing project documents: brand aliases/domains, offering/customer, market, conversion goal, known competitors versus discovered search competitors, relevant pages, owner exports, earlier reports and restrictions. No generated agent profile or second settings authority is needed.

## Present the result

Lead with the diagnosis and the most consequential actions, then a compact query → observed answer/result → cited/competing page → owned page evidence matrix. Put method, costs, freshness, rejected opportunities and coverage in the full report/answer. Save ordinary source reports and, when grouped, the initiating-thread answer; do not create a new SEO record schema.

Use `show_research` after reading the saved report/answer and the relevant originals when a native card will help. Supply a short title/statement, ordered detail labels such as Query / Cited page / Owned page, existing evidence file references, material limits and an optional proposed next-step prompt. Missing steps stay visible. The card's status and costs are derived from the saved files; do not supply invented authoritative fields. The optional draft action does not execute the change or send a message automatically.

## Follow-up and history

First use the provider's historical/change endpoints and previous Dig reports for a specific comparison. LLM Mentions database retrieval called Live is not necessarily a newly generated answer; inspect observation dates and current refresh documentation. Match target definitions, platform/market/language and date windows. Count changes and estimated-volume changes may use different rules.

Verify a page change separately from an acquisition outcome. A later citation/rank change does not by itself prove causation. Host-scheduled follow-up can be proposed when useful, but create a schedule only when requested. Callback completion is not an alert about a meaningful business change. Do not add a background monitor or a metrics warehouse to perform this workflow.
